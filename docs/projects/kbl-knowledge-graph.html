Wire Harness Knowledge Graph

Own project | 10/2026 | Developer

Real VW harness as a knowledge graph, live 3D demo

DataAI / SimulationKBLRDF/OWLSPARQLPythonThree.js
Open the live demo ↗3D routing ↗Code on GitHub ↗

What?

  • KBL (VDA 4964) describes the wire harness: connectors, wires, modules. Functions and control units live in the E/E model. Both only share names.
  • Goal: link both views in one semantic graph and answer questions that neither source can answer alone.

How?

  • Small ontology (OWL, 12 classes, labels in German and English, naming conventions) and a Python converter (rdflib) for KBL and E/E data.
  • SPARQL questions for traceability, change impact, variants and consistency; first on a fictitious door harness, then on the public VW “Old Beetle” sample harness (KBL 2.4).
  • 3D routing rebuilt from the KBL B-spline centre lines; interactive viewer (Three.js).

Results

  • 5 957 triples; variants compared: MAXI 254 connections and 278 m of wire, MINI 165 and 218 m.
  • Consistency checks found an empty module and 5 segments whose geometry does not match the topology.
  • Live demo (EN/DE): suavi-yildirim.github.io/bordnetz-knowledge-graph
